# Heat-Diffusion Agent Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Demonstrate a real, natural-language scientific workflow in which the reasoner creates a C/OpenMP 2D heat-diffusion experiment, validates it in the isolated Project, runs it on the VM Slurm allocation only after explicit approval, and produces convergence/scaling results with traceable Evidence and Capsule artifacts.

**Architecture:** The user creates a blank Project with a scientific goal. The embedded Pi Project Agent saves a typed Blueprint, writes all source files through digest-guarded patches, runs a bubblewrap validation, and schedules one bounded Slurm validation. A successful AgentTask becomes a server-derived formal-run candidate, removing manual copying of internal IDs while retaining a digest-bound approval. The formal Run uses a four-CPU allocation and nested `srun -c 1`, `-c 2`, and `-c 4` steps. A deterministic application-side validator audits the generated outputs; it never supplies solver source to the Agent.

**Tech Stack:** Python 3.11/3.12 stdlib, C11, GCC/OpenMP, Slurm 23.11 CLI, bubblewrap, Pi Agent Project tools, React/TypeScript, pytest, Vitest, VM HTTP/browser acceptance.

## Global Constraints

- The solver and experiment files must be generated by the configured reasoner from the user's goal. Do not commit a solver template and do not inject source files from the smoke script.
- Use the supported durable profile ID `campus-default` and require it to resolve to the deployed model ID `qwen3.8-reasoner`. The smoke must fail if `turn_completed` reports a different model and must record the actual provider/model.
- The scientific reference solution is
  `u(x,y,t) = sin(pi*x) * sin(pi*y) * exp(-2*pi*pi*alpha*t)` on `[0,1]^2`, with zero Dirichlet boundaries.
- Convergence grids are 64, 128, and 256. Observed spatial order must be within `[1.8, 2.2]`.
- Scaling uses one formal four-CPU Slurm allocation and records 1-, 2-, and 4-thread measurements via `srun -c 1`, `srun -c 2`, and `srun -c 4`. Do not claim linear speedup as a required scientific result.
- Required outputs are `raw-results.csv`, `convergence.json`, `scaling.json`, `report.md`, `convergence.svg`, and `scaling.svg`.
- Python post-processing uses only the standard library; the generated workflow has no network dependency.
- Sandbox execution must fail closed when bubblewrap is unavailable. Do not add a host-execution fallback.
- The user must separately approve validation resources, ChangeSet publication, and the exact formal-run digest.
- Each task ends with an isolated commit.
