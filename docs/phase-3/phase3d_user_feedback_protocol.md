# Phase 3D 轻量用户反馈协议

日期：2026-07-16  
状态：当前协议  
性质：产品反馈，不是人数门禁、统计性研究或真实平台验收。

## 目标

让可获得的本科生使用当前产品流程，发现界面、术语、预检、提交和 Evidence 理解上的问题。参与人数、完成率和用时不决定项目是否可以继续；反馈用于确定后续改进优先级。

## 环境

- 默认使用开发者本机的 `fixed_user` competition profile；
- 底层为 Docker Slurm simulator，必须向参与者说明不是真实 107；
- 参与者只使用浏览器，不获得 SSH、Docker、平台账号或开发者凭据；
- 需要远程共享环境时才部署 CPU VM 固定版本。

## 建议任务

1. 从模板市场寻找 Python CPU 模板；
2. 采用模板并尝试修改 workdir 和 command；
3. 阅读资源预检并说明自己的理解；
4. 创建和提交 Run；
5. 尝试找到 stdout 和结果文件；
6. 查看预置失败 Run，尝试找出失败原因及 Evidence；
7. 说明最困惑、最不信任或最希望简化的地方。

任务未完成、使用终端、需要提示或中途退出都属于有效发现，不应删除记录或判定参与者失败。

## 最小记录

- 匿名 participant ID，不记录姓名、学号、邮箱、IP 等个人信息；
- 测试日期、构建版本和环境等级 `D1` 或 `S1`；
- 每项任务的结果：完成、部分完成、未完成、跳过；
- 停顿、误解、提示和错误信息；
- 参与者反馈的原意，可做匿名转述；
- 若产生对象，记录 Contract ID、Run ID 和相关 Evidence URI；
- 观察者认为需要修改的界面或文案。

用时、是否使用终端和首次成功时间可以记录，但只用于理解摩擦，不设置通过阈值。

## 反馈评审

每轮结束后生成 findings-first 记录，每条至少包含：

- finding ID；
- 观察和复现步骤；
- 影响范围；
- P0/P1/P2/P3 严重度；
- 证据或对象 ID；
- 决定：修复、延期、拒绝或需要更多信息；
- owner 和目标切片；
- 修复后的验证结果。

P0/P1 在相关功能成为默认路径前必须清零。P2/P3 可以带明确 owner 进入 backlog。没有固定参与人数，也没有 `passed/failed` 的总体真人门禁。

## 与旧协议的关系

旧的 `phase3d_novice_acceptance_protocol.md`、`pilot107.novice-acceptance/v1` schema、evaluator 和 pending artifact 是此前五人硬门禁方案的历史证据。它们不删除、不伪造为通过，但从本协议生效起不再决定 Phase 3D/3E 的准入状态。
